
# CBR Loan Loss Provisions Copilot

[Русский](README.md) | **English**

**CBR Loan Loss Provisions Copilot** is a demonstration **Retrieval-Augmented Generation (RAG)** assistant that searches a curated collection of Bank of Russia regulations and supporting explanations and generates source-referenced answers.

Originally developed as an **MVP (Minimum Viable Product)**, the project showcases an end-to-end document-grounded AI workflow: ingestion, hybrid retrieval, context selection, local LLM inference, citations, evaluation, observability, and document export.

> **Demonstration only.** The assistant is not intended for professional credit decisions or regulatory compliance work. Generated answers may be inaccurate, incomplete, or based on outdated source documents. It does not calculate loan-loss provisions for individual borrowers.

## Why this project matters

The Russian banking regulations are **one use case**, not a restriction of the underlying architecture. The same approach can be adapted to English-language or multilingual knowledge bases in legal, compliance, financial, technical, or internal-document search by replacing the corpus, retrieval configuration, LLM, and evaluation criteria.

The implementation demonstrates practical experience with:

- RAG pipeline design and retrieval quality trade-offs;
- hybrid search, ranking, context selection, and fallback logic;
- structured answers and source attribution;
- resource-constrained local LLM deployment;
- LangSmith evaluation and hierarchical production-style tracing;
- Streamlit UI, runtime artifact preparation, and DOCX export.

## Features

- Search across selected source categories or the full knowledge base.
- Two answer modes: **regulation only** and **regulation + explanation**.
- Source references (citations) alongside generated answers.
- Hybrid retrieval, deduplication, ranking, and context selection.
- Copyable results and exportable DOCX summaries.
- Evaluation on a 10-question reference set and stage-level tracing in LangSmith.

## Knowledge base

The demonstration corpus includes four prepared sources:

| Type | Source |
| --- | --- |
| Primary | Bank of Russia Regulation No. **590-P** — loan-loss provisions for loans and equivalent exposures |
| Primary | Bank of Russia Regulation No. **611-P** — provisions for possible losses |
| Secondary | Structured explanations and Q&A concerning 590-P (166 normalized Q&A records) |
| Secondary | PDF explanations concerning 611-P |

Regulations are treated as primary evidence; explanations supplement rather than replace them. Retrieval combines keyword-oriented and semantic matching appropriate to the source type.

The knowledge base is a **fixed snapshot**. Regulatory updates are **not** synchronized automatically. The original PDF/XLSX source files are excluded from Git; a validated, ready-to-use Chroma index (583 entries) is distributed in `deployment/chroma_index_mvp.zip`.

## Architecture

```text
PDF / XLSX → ingestion + metadata → embeddings → Chroma
                                                │
User question → Streamlit → hybrid retrieval → selection/ranking
                           → context formatting → local GGUF LLM
                           → structured answer + citations
                           → UI / copy / DOCX export
```

Key modules:

- `rag/ingest/` and `rag/index_chroma.py`: document ingestion and indexing.
- `rag/retrieve_all.py`, `rag/retrieve_primary.py`, `rag/retrieve_secondary.py`, `rag/retrieve_hybrid.py`: retrieval and source-aware search.
- `rag/selection_utils.py` and `rag/context_formatter.py`: evidence selection and prompt context assembly.
- `rag/answer_pipeline.py`, `rag/answer_generator.py`, `rag/answer_contract.py`: orchestration, local LLM generation, and structured output.
- `app/streamlit_app.py`: user interface and report download.
- `deployment/bootstrap.py`: validates/downloads GGUF and restores/verifies the Chroma index without rebuilding it at each startup.

The output contract includes `answer`, `citations`, `grounded`, `answer_mode`, and `notes`. The `grounded` value is generated by the assistant's own pipeline; it is **not** an independently verified correctness score.

## LangSmith: evaluation and observability

The project uses a **10-question evaluation set**, with baseline artifacts in `evaluation/`. Locally verified tracing is integrated directly into the Streamlit application's RAG workflow:

```text
answer_question
└── run_answer_pipeline
    ├── retrieve_all
    ├── select_context_items
    ├── prepare_context_package
    └── generate_final_answer
```

Traces record execution time and compact metrics such as retrieval and selection counts, context length, citation counts, and response metadata. User questions and some response content may also be transmitted to LangSmith when tracing is enabled; do not submit confidential information.

Selected baseline metrics on the **limited 10-question dataset**:

| Metric | Result |
| --- | ---: |
| `retrieval_doc_recall` | 1.00 |
| `retrieval_clause_recall` | 1.00 |
| `citation_doc_recall` | 1.00 |
| `citation_clause_recall` | 0.60 |

These figures are **not general accuracy guarantees**. Profiling showed answer generation is the dominant latency contributor in the current CPU-only configuration.

## Quick start

**Prerequisites:** Python 3.12, an environment compatible with the pinned dependencies, and network access for the initial model downloads. Local development was performed on Windows / PowerShell; Linux deployment has not yet been validated end-to-end.

On Windows PowerShell, from the repository root:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m deployment.bootstrap
python -m streamlit run app/streamlit_app.py
```

`deployment/bootstrap.py` restores the included Chroma archive to `data/chroma/`, verifies the `cbr_llp_copilot` collection (583 entries), downloads the pinned public GGUF model to `data/models/` when needed, and validates its SHA-256. It does **not** re-ingest source documents at application startup. Embedding-model weights are downloaded from Hugging Face if absent from the local cache.

To **rebuild** the knowledge base from source documents, supply the four matching files in `data/raw_docs/` and run `python -m rag.index_chroma` only against a deliberately prepared index: the current indexer appends records and can create duplicates if rerun against an existing collection.

### Optional LangSmith tracing

Create a local `.env` (never commit it):

```dotenv
LANGSMITH_TRACING=true
LANGSMITH_PROJECT=cbr-llp-copilot-demo
LANGSMITH_API_KEY=<your-langsmith-api-key>
```

The application can answer questions with tracing disabled. When tracing is enabled, inputs and certain outputs are sent to the external LangSmith service.

## Demonstration deployment

**Streamlit Community Cloud** is the selected target, but the live deployment and cloud runtime have **not yet been validated**.

- GitHub contains source code, `requirements.txt`, and the compressed Chroma index.
- The GGUF model and multilingual embeddings are fetched from public Hugging Face repositories.
- The bootstrap module prepares the artifacts and prevents silently starting with an empty index.
- CPU-oriented cloud settings are planned: `LLAMA_N_THREADS=2`, `LLAMA_N_GPU_LAYERS=0`.
- The LangSmith API key and runtime configuration should be placed in **Streamlit Secrets**, never in Git.

The application's observed Windows Streamlit working-set peak was approximately **2.1 GB** during testing. This is not a reliable Linux memory-limit measurement; successful operation on Community Cloud remains to be confirmed.

## Limitations and future directions

- **Answer quality:** the compact local model may produce incomplete, overly extractive, or incorrect interpretations.
- **Source precision:** citations may reference a page or document rather than an exact regulatory clause; not every citation fully supports the answer.
- **Answer mode consistency:** In some scenarios, the returned `answer_mode` may differ from the user-selected mode. The issue may be related to local LLM generation or structured-output handling and requires further investigation.
- **Freshness:** the regulatory corpus is not automatically updated.
- **Performance:** CPU-based inference is slow and is not designed for high concurrency.
- **Scope:** no borrower-level credit-file processing, automatic risk grading, loan-loss calculation, or integration with bank core systems.

Potential improvements include stronger inference models, clause-level citations, refined retrieval/reranking, document freshness monitoring, additional corpora and languages, and infrastructure sized for production workloads.

**Project status:** the assistant and LangSmith tracing work locally; demonstration deployment preparation is complete, while public cloud deployment and end-to-end Linux validation are pending.
